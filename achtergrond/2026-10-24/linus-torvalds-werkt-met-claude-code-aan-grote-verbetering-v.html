Nieuwe kernelbranch vermeldt Claude Code als hulpmiddel
De poortwachter pakt zelf de AI-tool

Linus Torvalds werkt met Claude Code, de programmeerassistent van Anthropic, aan een omvangrijke verbetering van de Linux-kernel, meldt Phoronix. Zijn nieuwe kernelbranch noemt Claude Code als hulpmiddel. Welk deel van de kernel het betreft en hoe groot de AI-bijdrage precies is, vermeldt het bronbericht niet. De symboliek is evenwel groot. Torvalds begon Linux in 1991 als hobbyproject en is sindsdien de eindverantwoordelijke voor wat er in de kernel terechtkomt. Hij staat bekend om zijn scherpe oordeel over codekwaliteit en zijn ongeduld met slordige bijdragen. Juist binnen de kernelgemeenschap is de afgelopen jaren gediscussieerd over de vraag of en hoe door AI gegenereerde code welkom is. Dat de man aan de top het hulpmiddel nu openlijk vermeldt, verandert die discussie.

🔬 Hoe een patchserie de kernel bereikt
Van eigen branch tot opname in de officiële kernel
Branch

Het werk begint in een aparte Git-branch, los van de hoofdlijn.

Git, dat Torvalds in 2005 zelf schreef, laat ontwikkelaars veranderingen apart opbouwen. Torvalds' nieuwe branch is volgens Phoronix de plek waar Claude Code als hulpmiddel wordt genoemd.

AI-assistentie

Claude Code helpt bij het schrijven en herschrijven van een grote patchserie.

Zo'n assistent werkt in de terminal op de codebasis zelf en kan wijzigingen over veel bestanden voorstellen. De ontwikkelaar beslist wat blijft; welk aandeel de AI hier had, meldt de bron niet.

Review

Andere kernelontwikkelaars beoordelen de patches openbaar.

In de kernelwereld worden wijzigingen besproken door maintainers van de betrokken subsystemen. Juist die menselijke controle is het argument dat AI-hulp beheersbaar kan blijven.

Merge

Pas na goedkeuring gaat het werk de officiële kernel in.

Torvalds voegt wijzigingen samen tijdens de merge window van een nieuwe kernelversie. Of en wanneer deze branch die stap zet, is nog niet bekend.

Waarom dit meer is dan een anekdote

Open source drijft op vertrouwen in wie code schrijft en wie ervoor instaat. AI-assistentie maakt dat ingewikkelder: wie is verantwoordelijk voor een fout die een model voorstelde, en hoe zit het met auteursrecht op gegenereerde code? Door Claude Code expliciet te vermelden, kiest Torvalds voor transparantie in plaats van het gebruik te verzwijgen. Dat is ook een model voor anderen: niet de vraag óf AI wordt gebruikt staat centraal, maar of de mens die het werk indient het volledig begrijpt en verdedigt. Voor Anthropic is het een prestigieuze referentie. De kernel is een van de meest complexe en kritische codebases ter wereld; als het hulpmiddel daar zinvol blijkt, is dat een sterker argument dan welke benchmark ook.

Niet het gebruik van AI is de toets, maar of de mens die de code indient er volledig voor instaat.

Gevolgen en perspectieven

Voor de kernelgemeenschap betekent dit dat regels over AI-bijdragen concreter moeten worden: hoe vermeld je assistentie, en welke eisen gelden voor review? Ook bedrijven die Linux inzetten — van cloudaanbieders tot Europese overheden die op open source sturen — krijgen te maken met de vraag hoe AI-geassisteerde code wordt gecontroleerd. Sceptici zullen wijzen op risico's van subtiele fouten; voorstanders op productiviteitswinst bij omvangrijk, repetitief herstructureringswerk.

Conclusie

Torvalds' keuze is een kantelpunt in houding, niet in techniek. Wanneer de meest kritische reviewer van open source AI openlijk als gereedschap gebruikt, verliest het argument dat zulke hulp per definitie amateuristisch is zijn kracht. Wat blijft is de eis die Torvalds altijd stelde: de code moet goed zijn, wie of wat haar ook heeft helpen schrijven.
