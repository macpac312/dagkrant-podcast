Inbraak

Een onbevoegde derde komt in het beheersysteem.

Het advertentiesysteem komt van een externe leverancier en wordt beheerd door een aparte dienstverlener. Daar maakte een aanvaller ongeautoriseerde wijzigingen.

Advertentietag

Kwaadaardige code reist mee met de reclame.

De code werd toegevoegd aan een advertentietag die onder meer op VI.nl wordt gebruikt. Dezelfde technologie draait ook op andere websites.

Bezoek

De bezoeker hoeft niets aan te klikken.

Het laden van de pagina volstaat. De code stuurde IP-adres, bezochte pagina, verwijzende pagina, schermformaat, taalinstelling en besturingssysteem naar de aanvaller.

iPhone

Een tweede functie mikte op verouderde iPhones.

Gericht op modellen zonder de nieuwste beveiligingsupdates, zoals iPhone XS, XR, 6s, 7 en SE (eerste generatie). Gevolgen bij succes: mogelijke toegang tot wachtwoorden en cryptowallet-sleutels.

Wat er gebeurd is

Voetbalsite VI.nl waarschuwt voor kwaadaardige code die begin november via advertenties werd verspreid. Volgens VI zelf kon die code gegevens over websitebezoeken verzamelen, en probeerde hij op bepaalde iPhones toegang te krijgen tot persoonlijke gegevens. Het bijzondere aan de aanval is dat bezoekers niets hoefden aan te klikken: het openen van de pagina was voldoende. VI schrijft dat een onbevoegde derde zich toegang verschafte tot het beheersysteem van de advertentiedienst en daarin ongeautoriseerde wijzigingen aanbracht, waardoor de code aan een advertentietag kon worden toegevoegd. De code is inmiddels verwijderd en de kwetsbaarheid is verholpen, maar het onderzoek naar de gevolgen loopt nog. VI kan niet voor elke individuele bezoeker vaststellen of de code is geladen en welke gegevens zijn verzonden.

Waarom advertenties zo'n aantrekkelijke route zijn

De aanval is een voorbeeld van wat de beveiligingssector malvertising noemt: kwaadaardige code die via het reclamesysteem op betrouwbare sites terechtkomt. Voor de aanvaller is de aantrekkingskracht duidelijk. Hij hoeft de website zelf niet te hacken, maar alleen de schakel in de keten waar het toezicht het zwakst is. VI beschrijft zelf die keten: een softwareleverancier, een afzonderlijke beheerder, en de uitgever die de tag op zijn pagina's laadt. Eén zwakke schakel bereikt zo alle sites die dezelfde technologie gebruiken. De aanval was bovendien precies gericht: alleen toestellen met verouderde software kwamen in aanmerking, wat past bij een aanvaller die liever weinig opvalt dan veel slachtoffers maakt. Of daaruit blijkt wie erachter zit, kan uit het beschikbare materiaal niet worden afgeleid.

Wat bezoekers kunnen doen

VI adviseert iedereen die in de genoemde periodes met een verouderde iPhone de site bezocht, maatregelen te nemen; op de website staat een stappenplan. Een software-update beschermt tegen bekende kwetsbaarheden, maar maakt niet ongedaan dat bij een eerdere succesvolle aanval al gegevens zijn buitgemaakt. Het is dus zowel preventie als schadebeperking. Vooral bij mogelijke toegang tot opgeslagen wachtwoorden en cryptowallet-sleutels is het verstandig wachtwoorden te wijzigen. Voor de uitgever is er een ander dilemma: openheid over zo'n incident kost vertrouwen op de korte termijn, maar het zwijgen erover kost meer. Dat VI zelf een beveiligingswaarschuwing plaatste, is in dat licht een professionele reflex. De Autoriteit Persoonsgegevens kan bij een datalek meldplicht aan de orde stellen; of dat hier speelt, is nog niet duidelijk.

💡 Verklaard
Malvertising
Het verspreiden van schadelijke code via advertentienetwerken, zodat bezoekers van legitieme websites worden getroffen.
Advertentietag
Een stukje code op een pagina dat advertenties van een externe dienst laadt. Wie de tag manipuleert, bereikt iedere site die hem gebruikt.
Verouderde iOS
Telefoons zonder recente beveiligingsupdates missen patches voor bekende kwetsbaarheden; precies die lacunes buit de code uit.
Conclusie

Het VI-incident toont dat de veiligheid van een website zo sterk is als de zwakste partij in zijn advertentieketen. Uitgevers die inkomsten halen uit externe tags, dragen daarmee ook een deel van het risico. Voor gebruikers geldt de oudste regel in nieuwe vorm: houd software actueel. Voor uitgevers geldt een scherpere: weet wie er in jouw pagina meeschrijft.
