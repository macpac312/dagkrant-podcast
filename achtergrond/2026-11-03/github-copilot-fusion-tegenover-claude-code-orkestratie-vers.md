GitHub Copilot Fusion is sinds 28 oktober 2026 algemeen beschikbaar.

Fusion verdeelt werk over meerdere modellen; Claude Code laat één agent de hele taak uitvoeren.

Orkestratie kan kosten drukken: eenvoudige taken hebben geen topmodel nodig.

De vraag verschuift van 'welk model is het slimst' naar 'hoe werken modellen samen'.

Van één model naar een team van modellen

AI-codeertools leunen niet langer op één model voor elke taak. Dat is de kern van een vergelijking die Analytics Insight maakte tussen GitHub Copilot Fusion en Claude Code van Anthropic. Fusion, dat op 28 oktober 2026 algemeen beschikbaar werd na eerder onderzoekswerk onder de naam HydraFusion, kiest per taak verschillende modellen, afhankelijk van complexiteit en gevraagde inspanning. Claude Code gaat een andere weg: Anthropics eigen modellen plannen de taak, verkennen de codebase, bewerken bestanden, voeren terminalcommando's uit en testen hun eigen werk. Beide beloven ontwikkelaars werk uit handen te nemen, maar het ontwerp verschilt fundamenteel. Bij Fusion zit de intelligentie in de samenwerking tussen modellen, bij Claude Code in één agent die het hele traject doorloopt.

Hoe Fusion modellen laat samenwerken

Fusion kent drie werkwijzen. Bij Single doet één model de taak. Bij Cascade begint een goedkoper model; een beoordelend model controleert het resultaat en schakelt een sterker model in als de eerste poging tekortschiet. Bij Critique schrijft één model de code, beoordelen andere modellen die, en verbetert het eerste model zijn werk op basis van die feedback. Het voordeel is tweeledig: ontwikkelaars hoeven niet per taak een model te kiezen, en de kosten blijven lager omdat eenvoudige taken geen topmodel nodig hebben. Claude Code kan met subagents ook werk opsplitsen, bijvoorbeeld voor review, onderzoek of het schrijven van tests, maar dat is een andere werkwijze dan Fusions ingebouwde systeem van modellen die elkaar beoordelen.

Wat nu telt, is hoe modellen samenwerken, niet alleen hoe slim één model is.

Gevolgen voor teams en organisaties

Voor ontwikkelteams is de keuze minder technisch dan hij lijkt. Fusion past bij organisaties die vooral grip willen op kosten en kwaliteit per taak; Claude Code bij teams die grotere, samenhangende klussen aan een agent willen overlaten. Dat de praktijk weerbarstig is, bleek deze week bij Goldman Sachs, dat Claude Code en Copilot alleen nog aan engineers geeft en handelaren en bankiers de toegang ontneemt, terwijl de CIO in juli nog 'vibe coding' prees. Meer autonomie vraagt ook meer toezicht: een agent die zelf commando's uitvoert, verdient dezelfde controle als een nieuwe collega met beheerdersrechten.

Conclusie

De vergelijking laat zien dat de concurrentie tussen codeertools verschuift van modelkwaliteit naar architectuur. Orkestratie is een antwoord op de kostenvraag, autonomie een antwoord op de productiviteitsvraag. Beide benaderingen zullen naar elkaar toe groeien: Claude Code heeft al subagents, Fusion verdeelt al rollen. Wie nu kiest, kiest vooral hoeveel zeggenschap hij aan de machine wil geven.
