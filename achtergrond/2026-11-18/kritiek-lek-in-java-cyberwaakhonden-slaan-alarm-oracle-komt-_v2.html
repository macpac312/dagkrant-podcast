Waarom dit alarm klinkt

De nationale cyberwaakhonden van Zwitserland en Zuid-Korea waarschuwen voor een kritieke kwetsbaarheid in Java waarmee kwaadwillenden op afstand systemen kunnen overnemen zonder in te loggen, meldt het FD. Het Nederlandse NCSC onderzoekt de melding. Het lek zit in een onderdeel dat in Java 17 en latere versies wordt gebruikt, terwijl de huidige versie Java 27 is, en scoort 9,2 op de CVSS-schaal. Zo'n score duidt op een combinatie van weinig drempels voor de aanvaller en grote gevolgen voor het slachtoffer. Het Amerikaanse Calif, dat het lek als kritiek aanmerkte, deelt pas technische details nadat de update beschikbaar is; ook het Amsterdamse Hadrian en Wiz Security wijzen op het probleem. Voor zover bekend is er nog geen misbruik.

Waarom Java zo veel raakt

Java is geen product maar een fundament. Bedrijven draaien er bankplatformen, webwinkels en interne systemen op, en veel organisaties weten niet precies waar het allemaal draait, omdat de taal vaak diep in andere software is verpakt. Dat maakt het inventariseren van risico lastig en maakt dat een lek in een onderdeel van Java 17 en nieuwer een grote groep treft: versie 17 is een langdurig ondersteunde release die in bedrijfsomgevingen veel gebruikt wordt, ook nu de huidige versie 27 is. De waarschuwing komt bovendien kort na het PHP-lek, dat Calif een maand geleden ontdekte en waarna veel Nederlandse websites op zwart gingen. Dat voorbeeld laat zien hoe snel een technische kwetsbaarheid in een brede webtaal maatschappelijke impact krijgt. Dat er voor Java nog geen misbruik bekend is, zegt weinig: aanvallers kunnen pas actief worden zodra details openbaar zijn.

Het gevaar zit niet in het lek zelf, maar in de tijd tussen patch en uitrol.
Wat organisaties nu moeten doen

Voor Nederlandse organisaties is de les praktisch. Zoek uit waar Java draait, ook in verpakte producten, en zorg dat de update dinsdagavond snel kan worden getest en uitgerold. Het NCSC onderzoekt de melding; officiële adviezen volgen waarschijnlijk zodra de update er is. Voor kleinere partijen die afhankelijk zijn van leveranciers geldt dat zij moeten navragen of die leveranciers hun Java-onderdelen bijwerken.

Conclusie

Er is nog niets stuk, en dat is precies het moment om te handelen. De gecoördineerde aanpak met eerst een waarschuwing en daarna een patch is goed ontworpen, maar werkt alleen als beheerders snel zijn. Bij elk kritiek Java-lek geldt: de race begint niet bij de ontdekking, maar bij het uitkomen van de update.
