Het jaar waarin de machines gingen committen

Het Octoverse-rapport van GitHub is al jaren de thermometer van de software-industrie: hoeveel ontwikkelaars er zijn, welke talen groeien, welke landen het meest bijdragen. Dit jaar meet de thermometer koorts. Op de conferentie GitHub Universe presenteerde EVP Jay Parikh cijfers die Simon Willison, als gast aanwezig, "een vrij scherpe weergave van de impact van agentic engineering" noemt. Het aantal gemergde pull requests verdrievoudigde in minder dan een jaar tot 220 miljoen per maand. Commits stegen meer dan driedubbel tot 7,38 miljard per maand, met het grootste deel van die toename in de tweede helft van het jaar. Het tempo waarin nieuwe repositories worden aangemaakt, verdubbelde tot 30,3 miljoen per maand. Zulke sprongen passen niet bij organische groei van het aantal menselijke ontwikkelaars. Ze passen wel bij software die zelf code schrijft en indient.

Hoe een agent het werk verandert

De verklaring ligt in de manier waarop programmeren in 2026 is veranderd. Een ontwikkelaar geeft een opdracht, een agent als Copilot, Claude Code of Codex zoekt in de codebase, schrijft wijzigingen, draait tests en opent een pull request. Elk van die stappen laat sporen na in de statistieken, en omdat agents kleinere, frequentere commits maken en meerdere taken parallel uitvoeren, groeit het volume harder dan het aantal mensen erachter. Dat de versnelling vooral in de tweede helft van het jaar zit, sluit aan bij andere signalen. OpenAI meldde deze week in Berlijn dat het aantal wekelijkse Codex-gebruikers in Duitsland sinds januari twintig keer zo groot is geworden. Google opende Android Studio voor ruim veertig externe coding-agents. Opvallend is ook de nieuwe categorie in het rapport: repositories over interoperabiliteit en reverse engineering, zoals clean-room-implementaties en drop-in-vervangers, een soort werk dat agents goedkoop maken.

Opdracht

Een ontwikkelaar beschrijft een taak in gewone taal en geeft die aan een agent.

Tools als Copilot, Claude Code en Codex werken direct in de repository. Eén mens kan zo meerdere agents tegelijk aansturen, wat de verhouding tussen mensen en activiteit op GitHub verandert.

Commits

De agent werkt in kleine stappen en legt elke wijziging vast als commit.

Agents proberen, testen en corrigeren in korte cycli. Dat verklaart waarom commits harder groeiden dan pull requests: meer dan een verdrievoudiging, met de piek in de tweede helft van 2026.

Pull request

De agent bundelt het werk in een pull request ter beoordeling.

Automatische tests en vaak ook een AI-reviewer beoordelen de wijziging. Hier zit het nieuwe knelpunt: menselijke reviewers moeten een veelvoud aan voorstellen controleren.

Merge

Na goedkeuring gaat de wijziging de hoofdcode in.

Het aantal gemergde pull requests verdrievoudigde in minder dan een jaar tot 220 miljoen per maand. Elke merge is software die in productie kan belanden, met nieuwe functies én mogelijke nieuwe lekken.

Meer code, meer zorgen

De keerzijde van al die productiviteit staat elders in deze krant. Het FD telde dit jaar 87.000 gemelde softwarelekken, 82 procent meer dan vorig jaar, en ziet dat agents kwetsbaarheden sneller vinden dan organisaties ze kunnen dichten. Meer code betekent meer aanvalsoppervlak en meer onderhoud. Ook de methodologie van GitHub laat zien hoe diep AI inmiddels in de meting zelf zit: landen worden toegekend via LLM-classificatie van profielen, om vertekening door VPN-gebruik te corrigeren, en repositories worden met een getraind embeddingmodel in bedrijfssectoren ingedeeld. Dat is pragmatisch, maar het maakt vergelijkingen met eerdere jaren minder hard. Voor Nederlandse bedrijven is de les dubbel. Wie agents inzet, haalt snelheid binnen; wie de review- en beveiligingscapaciteit niet meeschaalt, haalt ook risico binnen.

💡 Verklaard
Agentic engineering
Softwareontwikkeling waarbij AI-agents zelfstandig meerstapstaken uitvoeren: code lezen, wijzigen, testen en indienen. De mens stuurt en beoordeelt in plaats van elke regel te typen.
Commit versus pull request
Een commit is één vastgelegde wijziging. Een pull request bundelt commits tot een voorstel dat wordt beoordeeld en daarna in de hoofdcode wordt opgenomen (gemerged).
Interoperabiliteit en reverse engineering
Nieuwe Octoverse-categorie: projecten die bestaande software of protocollen namaken of vervangen, zoals clean-room-implementaties en drop-in-vervangers. Agents maken zulk werk veel goedkoper.
Conclusie

De Octoverse-cijfers zijn het eerste harde bewijs op platformschaal dat agents geen demo meer zijn maar het grootste deel van de nieuwe activiteit op GitHub kunnen verklaren. Toch meet een verdrievoudiging van commits volume, niet waarde. De echte vraag voor 2027 is of de kwaliteit meegroeit, of dat de industrie een berg code opbouwt die niemand volledig heeft gelezen. Wie het beoordelen van code niet net zo serieus automatiseert als het schrijven ervan, verplaatst het knelpunt alleen maar.
