Van AEO naar agent experience

Waar houdt answer engine optimization op en begint agent experience? Zeno Rocha, mede-oprichter en CEO van Resend, vertelt in de Latent Space-podcast hoe zijn bedrijf documentatie en tools ontwerpt zodat AI-agents als Claude Code de e-mail-API kiezen en kunnen gebruiken. AEO gaat over de vraag of een model je kent en aanbeveelt; agent experience over de vraag of een agent je product daadwerkelijk kan toepassen. Resend schreef sinds 2024 over AEO en sinds februari 2025 over agent experience. Het bedrijf had bij het opnemen 4,3 miljoen gebruikers en 120.000 betalende klanten, voor een aanbieder die in een markt van grote gevestigde spelers is begonnen, en vond een daarvan, Warner Bros. Discovery, door op een zaterdag korte .com-domeinen in de klantendatabase te sorteren.

🔬 Hoe een agent een e-mailaanbieder kiest
Van verzoek tot MCP-gebruik in vier stappen
Opdracht

Een ontwikkelaar vraagt een agent om e-mailverzending in te bouwen.

De agent kiest zelf een aanbieder. Wie het verzoek doet, kijkt zelden verder dan het eerste voorstel: de agent is de poortwachter.

Docs lezen

De agent haalt documentatie op en leest die als platte tekst.

Resend voegt .md aan de url toe zodat een prijstabel in één verzoek leesbaar is, terwijl een prijsslider voor een agent onbruikbaar is. Zo wint leesbaarheid voor machines.

Keuze

De agent kiest en schrijft code; de patch wordt geaccepteerd.

In een onderzoek koos Claude Code in 64 van 102 aanbevelingen eerst voor Resend. SendGrid stond zeven keer eerst en 55 keer als alternatief. Wie accepteert de patch, probeert zelden de tweede keuze.

Gebruik

Via de MCP-server doet de agent ook wat in het dashboard kan.

Resends MCP-server groeide van circa 20 tools naar meer dan 80. Zeno Rocha wil dat wie in een chatclient werkt hetzelfde kan als in het dashboard: van een demo naar echt beheer.

De ontwikkelaar komt eerder dan het model

Resends eerste distributiemiddel was een e-mailsjabloon. Terwijl het team de verzend-API bouwde, klaagden ontwikkelaars over de moeite om de e-mail zelf mooi te krijgen. Daarom kwam React Email, waarmee je een template kon bouwen en via SendGrid kon versturen, zelfs met documentatie. Toen een ontwikkelaar uiteindelijk een andere aanbieder zocht, stond een deel van Resends code al in de repository. De gastheren van de podcast vroegen zich af waarom agents steeds Resend voorstellen, terwijl zij zelf liefhebbers zijn van Cloudflare Email, dat voor wie al zijn domeinen bij Cloudflare heeft handig is en bovendien een thuisvoordeel kent. Voor een agent die aanbieders vergelijkt, geldt een andere route: leesbare docs, tabellen in plaats van sliders, en een MCP-server die opgroeide van ongeveer 20 tools naar meer dan 80. Interessant is dat de ontwikkelaar eerst komt en het model later: wie al code van Resend in zijn repo heeft, krijgt eerder een agent die daarop voortbouwt. Een nuance is dat een recentere, uitgebreidere AEO-studie competitiever uitviel, met Postmark bovenaan bij de meeste modellen. De 64 van 102 is dus een momentopname, geen wet.

Agent experience
Hoe goed een agent je product kan kiezen, begrijpen en gebruiken: leesbare docs, duidelijke fouten, complete tools.

Een standaardkoppeling waarmee een agent tools van een dienst kan aanroepen vanuit een chatclient of editor.

Open-source bibliotheek voor e-mailsjablonen in React, die als distributiekanaal diende.
Zeno Rocha wil dat iemand in een chatclient alles kan doen wat hij in het dashboard kan, zodat een agent verder komt dan alleen een demo.
Gevolgen voor de markt

Als agents de kopersrol overnemen, verschuift concurrentie van zichtbaarheid bij mensen naar leesbaarheid voor machines. Het lijkt op SEO, maar de impact is groter, en de feedbacklus korter, omdat een agent niet alleen verwijst maar ook uitvoert. De risico's zijn evenzeer scherp: een ontwerp voor agents zonder zorgvuldige standaardinstellingen kan fouten vergroten, zoals de 35.578 van 37.571 Grok Build-apps tonen die zonder inlog toegankelijk waren omdat 'iedereen met de link' standaard aanstond. Voor grote spelers als Cloudflare, die een thuisvoordeel hebben, wordt het lastig als de agent die voordelen niet ziet. Tegelijk bieden uitgebreide tooling en goede docs ook kleinere partijen de kans om in te breken. Ook modelbouwers als Anthropic spelen een rol: modellen die code schrijven, bepalen mede welke diensten worden gebruikt, een positie die toezichthouders en concurrenten zullen willen volgen.

Conclusie

Resends verhaal is een lesje in distributie in het agenttijdperk. Wie wil dat een agent hem kiest, moet zijn product leesbaar, compleet en voorspelbaar maken. Dat is een legitieme vorm van marketing, zolang het geen verborgen sturing van modellen wordt. De vraag voor de komende jaren is wie bepaalt wat de default is: de agentbouwer, de dienst of de ontwikkelaar die de patch accepteert.
