Together AI Hurdle Tests Claude Code and Codex Agents

Together AI's Hurdle lets developers evaluate Claude Code and Codex on real API tasks, compare their results, and test safeguards against unwanted actions. Illustrative scene. Image generated by ChatGPT.

An AI coding agent could find the cheapest GPU cluster, produce the right command, and still fail the task by accidentally purchasing one.

Together AI wants developers to catch mistakes like that before agents interact with real services. On Nov. 25, the company released Hurdle, an open-source testing framework that measures how well Claude Code and Codex use APIs, documentation, and developer tools.

Rather than relying on generic coding benchmarks, Hurdle lets companies test tasks their own customers might attempt. It can also compare how agents perform with different instructions, skills, and connections.

How Hurdle tests whether AI agents can use a platform

According to Together AI's announcement, Hurdle was developed through six months of internal testing before being released as an npm library.

Developers start by writing a task for an agent such as Claude Code or OpenAI's Codex. Hurdle then runs the task, records what the agent does, and evaluates the result.

Together's example asks an agent to identify the cheapest available GPU cluster and generate a reservation command without actually creating the cluster.

The agent must retrieve current availability and pricing, but a guard prevents it from submitting a real reservation.

Hurdle can repeat the same task across different models and conditions, then compare success rates.

For example, a developer could test whether adding a Model Context Protocol (MCP) server improves an agent's ability to navigate an API.

Results include pass rates, execution times, costs, and recorded sessions that developers can inspect to understand failures.

What eWeek found: The safety controls depend on how Hurdle runs

Hurdle offers two execution modes, and the distinction is important.

Local runs launch Claude Code or Codex directly on a developer's computer. They're convenient for simple evaluations but don't provide Hurdle's API request monitoring or guards.

Together warns that locally running agents can access the user's files and real API credentials.

Sandboxed runs place each agent in a fresh, isolated environment. A local proxy called Guardian routes network requests, checks them against configured rules, and substitutes real API credentials for temporary stand-ins.

When an agent attempts a prohibited API request, Guardian can reject it before the request reaches the service.

However, sandboxing doesn't automatically prevent expensive or unwanted operations. Together says agents can access any permitted API endpoint by default unless developers configure specific guards.

The company recommends using dedicated credentials with a low balance and explicitly blocking dangerous actions.

Hurdle also starts agents with a clean configuration. Developers can introduce specific skills or MCP servers as test conditions, but results won't necessarily represent how an agent behaves with every extension installed in its normal working environment.

That distinction is important because research into AI coding tools has found that measured performance can vary depending on the task and testing conditions.

Together hasn't published an independent assessment of Hurdle's evaluation accuracy or Guardian's security protections.

Getting started

Hurdle requires Node.js 22.18 or later and an installed Claude Code or Codex CLI.

Developers can initialize a project with npx hurdle init and start the example evaluation using npx hurdle run --view.

Sandboxed testing additionally requires Together API access and credits. Guardian's setup currently supports macOS and Linux.

The tool gives developers a way to measure whether AI agents understand their platforms, including where documentation or API design causes failures. But a high pass rate isn't proof that an agent will behave reliably or safely in production.

Teams should test representative tasks repeatedly, inspect failures, and verify that the safeguards they need are actually enabled.
