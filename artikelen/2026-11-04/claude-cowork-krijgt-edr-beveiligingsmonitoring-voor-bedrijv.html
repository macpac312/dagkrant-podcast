Anthropic Adds EDR Security Monitoring to Claude Cowork for Enterprise Users

Anthropic has introduced beta support for running endpoint detection and response sensors inside Claude Cowork’s local virtual machine, giving enterprise security teams visibility into activity that existing host sensors cannot inspect.

The integration supports Team and Enterprise plans on Claude Desktop for macOS and Window. The capability also works with Claude Desktop connected to Amazon Bedrock, Google Cloud Vertex AI, or Microsoft Foundry.

However, coverage stops at the local device: organizations cannot install their sensors in cloud Cowork sessions hosted on Anthropic’s infrastructure.

Anthropic Adds EDR Security Monitoring

Cowork executes shell commands and code inside an isolated virtual machine. While that separation creates an execution boundary, the endpoint security sensor installed on the surrounding computer cannot see inside it.

Installing a vendor sensor within the guest environment brings that activity into the security console organizations already use.

At each VM startup, Claude Desktop copies the configured sensor package into the environment and verifies its signature against the approved key for the specified vendor.

A valid signature allows Claude to execute the vendor’s installation script, at most once per VM start. Without configuration, no sensor is installed. The sensor then connects to its vendor’s cloud service and reports activity.

Notably, its telemetry and data transfers can bypass Cowork’s network allowlist, creating an important distinction between ordinary workload networking restrictions and security monitoring traffic.

Approved vendors currently include CrowdStrike, Evoke Security, Neo, Palo Alto Networks, Pluto Security, SentinelOne, and Tanium. Claude Desktop accepts only packages signed using an approved vendor’s key.

Administrators need Claude Desktop version 4.4212.0 or later. Windows deployments require the .msix build on Windows 10 or 11, with hardware virtualization and the Virtual Machine Platform feature enabled.

Configuration requires mobile device management on macOS or registry policy management on Windows through tools such as Group Policy or Intune.

Anthropic’s enterprise policy documentation identifies coworkEDRIntegration as the signed package’s full path and coworkEDRIntegrationVendor as the lowercase vendor identifier.

Windows administrators configure both under the machine-level Claude policy registry location. Each vendor supplies its own installation files and instructions.

The sensor can inspect VM activity and content, including prompts, files, and Claude responses. That information goes to the chosen EDR vendor; Anthropic says it neither receives nor controls the data.

Organizations must also manage lifecycle limitations. Removing configuration does not uninstall an existing sensor, but prevents package execution at subsequent VM starts.

Package signatures do not cover updates the sensor downloads later, and signatures expire within two years, requiring replacement with a newly signed package.

Anthropic charges no additional integration fee during beta, although vendors may charge separately. Customers remain responsible for testing before deployment and after updates to Claude or the EDR software.
