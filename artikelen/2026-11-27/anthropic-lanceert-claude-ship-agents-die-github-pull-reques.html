Anthropic Claude Ship: GitHub AI Code Reviews, Fixes, and Approvals - TechRepublic

Anthropic’s Claude Ship brings AI-powered reviews, fixes, and approvals to GitHub pull requests. Here’s how its three agents work, what they cost, and where human reviewers remain essential.

Anthropic's Claude Ship introduces AI agents that review GitHub pull requests, address code issues, and approve changes according to team-defined policies. Illustrative scene. Image generated by ChatGPT.

Writing the code is often only half the battle. A pull request can spend hours waiting for someone to review it, fix a failing test, resolve a merge conflict, or give the final approval.

Anthropic wants Claude to handle more of that work. On Nov. 23, the company introduced Claude Ship, a set of three AI agents that can review GitHub pull requests, address problems, and approve changes under rules set by the development team.

The feature is available to organizations on Claude Team and Enterprise plans. Code Review is already generally available, while PR Steward and Claude Approvals are in beta. Teams can decide which repositories use the agents and which changes still require human approval.

How Claude Ship reviews, fixes, and approves code

According to Anthropic’s announcement, Claude Ship divides the work that follows a pull request into three stages.

Code Review uses multiple specialized AI agents to examine a pull request and its surrounding codebase. They look for logic errors, security vulnerabilities, broken edge cases, and potential regressions.

The agents check their findings before posting comments directly on the affected lines of code.

Reviews distinguish between problems that should be fixed, minor suggestions, and bugs that existed before the pull request.

Importantly, Code Review doesn’t approve or block a merge on its own. It provides findings that developers and existing approval workflows can act on.

Anthropic says reviews take approximately 20 minutes on average, although timing depends on the size and complexity of the code.

PR Steward takes over some of the follow-up work that normally sends developers back to code they’ve already finished.

If continuous integration (CI) checks fail, a merge conflict appears, or a reviewer requests changes, the agent can investigate and push a proposed fix.

After each push, it posts a comment explaining what changed and how to undo the modification.

Developers can give it further instructions using @claude or tell it to stop using @claude stop.

PR Steward is designed not to approve or merge pull requests. Those decisions remain subject to the team’s review process and repository rules.

Claude Approvals takes a different approach to code approval. Instead of requiring the same review process for every change, teams write rules describing when Claude may approve a pull request and when a person must sign off.

Those rules live in a repository policy file, .claude/approvals.yml.

For example, a team could allow Claude to approve a routine documentation correction while requiring a human reviewer for changes to authentication, billing, or deployment infrastructure.

Claude’s approval counts as a real GitHub approval. Depending on the repository’s branch-protection rules, that approval could be enough to satisfy a merge requirement.

Anthropic recommends starting in observe-only mode, where Claude reports the decision it would make without issuing an approval.

That gives teams a chance to compare its decisions with human reviewers before granting the agent authority.

How developers and administrators can get started

Developers don’t have to wait for their organization to enable the full suite.

Anthropic has introduced a /ship command in Claude Code that lets developers try the workflow on their own pull requests.

Running /ship can create a pull request, perform a review, address issues, and watch for subsequent feedback.

However, this developer-controlled workflow isn’t identical to the organization’s cloud-based PR Steward service.

The local /ship command operates within the developer’s session. Monitoring stops when the session ends or the computer goes to sleep. On Windows, the command can open and review a pull request, but its watch function doesn’t start.

It can also commit pending changes in eligible private repositories, so developers should check git status before running it.
