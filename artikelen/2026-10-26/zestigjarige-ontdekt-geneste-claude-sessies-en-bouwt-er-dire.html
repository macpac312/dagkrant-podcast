Turning 60, I got a taste for Claude's nested sessions and immediately turned it into a skill｜goo

I'm 60 years old. Everyone, are you running Claude in parallel using nested sessions? This is truly convenient, isn't it? I think building AI agents was a trend around June, and it feels like we can now reproduce that using code on Claude Desktop.

And then I had an idea. If I could turn the process from brainstorming to document creation into a skill, couldn't I summon an AI agent team for different tasks every time...?

The plan is as follows. The parent session acts as an orchestrator to oversee overall progress. Under the parent, the child sessions have specific roles for each layer. And importantly, child sessions basically don't get their context polluted. This is amazing!

Parent session → Oversees overall progress only, sends/receives child session context Child session 1 → For brainstorming (brainstorming from draft to finalizing specifications) Child session 2 → Specification document creation Child session 3 → Devilish reviewer Child session 4 → Specification final draft acceptance & implementation Child session 5 → Testing Child session 6 → Debugging Child session 7 → Document creation

Loops are possible between child sessions 2 and 3, as well as 4, 5, and 6. This is because rejections can occur during reviews and debugging. In my actual experience running it, the review had to be redone three times.

Wait? You might be thinking, 'Isn't that strange? If a rejection occurs, won't the child session's context get polluted?' You're sharp! Anticipating that, I basically treat child sessions as disposable. The destination of a rejection becomes a new child session. So then you might ask, 'How do you share information?' I do this by updating files for each agent's work unit to share information.

I'm reusing an idea from an AI agent I built in the past, where I prepared a backend database to share progress and results among agents when they were related.

However, there is one concern regarding the workflow. My environment is Linux Mint, and since Claude Desktop is also the Linux version, I don't know how it behaves on other OSs, but the Linux version's nested sessions are currently designed so that the latest active child session always comes to the top. This means there is a possibility that you might not be able to tell at a glance which child session is currently working. This is most likely to happen when you get a rejection.

So, I made it possible to rename the session names in the left pane of Claude Desktop via a skill.

This change surprised me too, but it seems to exist as a specification.

This is extremely convenient because you can check which child session is currently running and what the chronological order is.

Trivia from here: I didn't know this at the time of writing, but if you mouse over the project name in the left pane of Claude Desktop, an icon labeled 'Group and Sort' appears. Click that, and when the menu is displayed, click 'Sort'. Since the default value is 'Last Updated', you can reduce session scattering by setting it to 'Created Date' or 'Name'. Incidentally, if you ask Claude to 'sort by creation date', it will change it for you. End of trivia.

The trigger to summon the AI agent team is set to activate using both Claude Code's memory and skills.

I personally like manual confirmation, so there are limits to parallel operation, but if you set it to auto-mode, it's possible that tasks might proceed in parallel on their own. Please give it a try.
