Wat is een MCP-server en wat veranderde er in 2026

Het Model Context Protocol is een open standaard om AI-assistenten aan externe systemen te koppelen. Anthropic introduceerde het eind 2024 met een simpel idee: ontwikkelaars stellen hun data beschikbaar via MCP-servers, of ze bouwen AI-toepassingen (MCP-clients) die met die servers praten. Eén protocol vervangt de losse, per aanbieder gebouwde koppelingen.

Een MCP-server kan drie soorten dingen aanbieden. Tools zijn acties die het model zelf kan starten, zoals een notitie opslaan. Resources zijn gegevens die de client kan inlezen, zoals een lijst met recente notities. Prompts zijn herbruikbare opdrachtsjablonen die de gebruiker kiest. In deze tutorial bouw je alle drie.

Sinds 2026 is er veel verschoven. De specificatie 2026-07-28 is volgens de maintainers de grootste herziening sinds de lancering. Ze introduceert een stateless protocolkern, Multi Round-Trip Requests, routering op basis van headers, cachebare lijstresultaten, aangescherpte autorisatie en een formeel raamwerk voor extensies. Red Hat noemt het stateless HTTP-transport specifiek bedoeld voor serverless en horizontaal schaalbare agent-workloads, zie het blog over de MCP-gateway voor OpenShift.

Ook het beheer veranderde. MCP is niet langer alleen van Anthropic, want het protocol is ondergebracht bij de Agentic AI Foundation. Anthropic legt die stap uit in zijn bericht over het doneren van MCP aan de AAIF. Voor jou als bouwer betekent dat vooral zekerheid: de standaard hangt niet af van één bedrijf.

De officiële referentieservers maakten dezelfde overstap. Versie 1.0.0 gold op 11 oktober 2026 als laatste release van het legacy-tijdperk, met alleen bug- en beveiligingsfixes. Volgens de releasepagina vormt versie 2.0.0 de moderne lijn, die legacy-clients nog steeds bedient. Nieuwe servers richt je dus op de stateless specificatie en op SDK-versie 2, en je bepaalt bewust of oudere clients nog moeten werken.

Ook de rest van de markt beweegt mee. Anthropic meldde op 22 oktober 2026 dat de connectoren-directory van Claude meer dan 75 koppelingen telt, allemaal gebouwd op MCP. Microsoft bracht op 12 oktober 2026 Azure MCP Server 3.0 uit als stabiele versie. En met Skills over MCP groeit het protocol van pure toolkoppeling naar het aanbieden van herbruikbare agent-vaardigheden. Bloomberg beschrijft zijn rol daarin in het stuk Skills over MCP. Wie dat deel wil begrijpen, begint bij ons artikel over Claude Skills bouwen met een SKILL.md.

Stand van zaken op 23 oktober 2026

Dat laatste punt is geen toezegging. De maintainers bespraken half september 2026 een releasecyclus van ongeveer acht maanden, met grote releases in maart en september. Plan je code dus niet rond een datum, maar rond de versie die je pint.

Je hebt een laptop met macOS, Linux of Windows nodig en een terminal waarin je je thuis voelt. Python-kennis op beginnersniveau volstaat, want de code is kort en elke regel krijgt uitleg. Reken op 90 minuten als je alles zelf typt en op 40 minuten als je de code kopieert.

Controleer eerst wat je hebt. Zonder uv installeer je het via de instructies op de projectpagina van uv, want de installatiemethode verschilt per besturingssysteem.

Een gezonde uitvoer ziet er zo uit. De exacte nummers verschillen bij jou, zolang Python op 3.11 of hoger zit.

Dat is één bron, dus controleer de actuele README van de SDK. De code hieronder gebruikt de high-level FastMCP-API. Draai de test uit stap 8 na elke SDK-update, zodat je breuken meteen ziet.

Het project: een notitie-server die Claude kan lezen en schrijven

We bouwen geen speelgoedvoorbeeld met een hello world-tool. De server slaat notities op in SQLite en laat een AI-client erin zoeken, schrijven, opruimen en exporteren. Zo leer je alle drie de primitieven en de lastige praktijkdingen: opslagpad, foutmeldingen, logging en tests.

Dit ontwerp volgt een regel die elke MCP-bouwer leert: weinig tools, duidelijke namen, kleine uitvoer. Een model kiest tussen vier scherp afgebakende tools veel betrouwbaarder dan tussen veertig overlappende. Wie zelf agents bouwt, ziet hetzelfde terug in een eigen agentlus, bijvoorbeeld in ons stuk over het Microsoft Agent Framework.

db.py bevat alleen SQLite-code en weet niets van MCP. server.py bevat de MCP-laag en roept db.py aan. Door die scheiding test je de opslag los van het protocol, en vervang je SQLite later door iets anders zonder de tools aan te raken.

Fase 1: het project opzetten (stap 1 tot 3)

Stap 1: maak de projectmap aan

Open een terminal en laat uv het skelet maken. De vlag --app zorgt voor een toepassing zonder bibliotheekstructuur, en dat is wat je hier wilt.

uv schrijft een pyproject.toml, een .python-version en een voorbeeldbestand. Dat voorbeeldbestand verwijder je, want je schrijft zelf server.py. De uitvoer van uv init is kort en meldt dat het project is aangemaakt.

Stap 2: installeer de MCP-SDK

Voeg het officiële mcp-pakket toe. De extra cli brengt het mcp-commando mee, dat je later gebruikt om te debuggen. Voeg meteen de testpakketten toe als ontwikkelafhankelijkheid.

De laatste regel bewijst dat het pakket in de projectomgeving staat. Noteer het versienummer dat je ziet. Pin die versie in pyproject.toml zodra je server in gebruik gaat, zodat een SDK-update niet stilletjes je tools breekt.

Stap 3: schrijf de databaselaag

Maak db.py. Het bestand regelt de verbinding, het opslagpad en vijf kleine functies. Let op het opslagpad: het komt uit een omgevingsvariabele met een vaste standaardwaarde in je thuismap. Een relatief pad is de meest gemaakte fout bij MCP-servers, omdat elke client de server vanuit een andere werkmap start.

Twee keuzes verdienen uitleg. Alle queries gebruiken vraagtekens als parameters en nooit stringopbouw, zodat een model dat vreemde zoektermen instuurt geen SQL-injectie kan veroorzaken. En de WAL-modus laat meerdere processen tegelijk lezen, wat handig is zodra twee clients dezelfde server starten.

Het getal 1 betekent dat de eerste rij is opgeslagen. Verwijder /tmp/rooktest.db daarna, zodat je testdata niet in je echte database belandt.

Fase 2: de server bouwen (stap 4 tot 6)

Stap 4: de eerste tool en de startregel

Maak server.py. Begin klein: één tool, logging naar stderr en de startfunctie. De logging verdient aandacht. Bij het stdio-transport leest de client alles wat je server naar stdout schrijft als protocolverkeer, dus een gewone print() breekt de verbinding. Alles wat voor jou bedoeld is, gaat naar stderr.

De docstring is geen decoratie. De SDK gebruikt hem als toolbeschrijving en het model leest die beschrijving om te beslissen wanneer het de tool aanroept. Schrijf hem als een instructie met een duidelijk gebruiksmoment. De typehints (str, list[str] | None) worden automatisch het invoerschema. En een ValueError komt bij de client aan als nette foutmelding in plaats van als crash.

Je ziet niets. Dat klopt, want de server wacht op berichten van een client. Stop hem met Ctrl+C.
