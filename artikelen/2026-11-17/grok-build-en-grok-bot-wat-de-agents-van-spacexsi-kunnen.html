Grok Buildとは。機能・料金・注意点｜土門大貴/daikidomon

SpaceXAI(旧xAI)のコーディングエージェント「Grok Build」を、Claude CodeやCodexと比べながら整理します。

「Grokのエージェント」は2種類ある

GrokをつくるxAIは、2026年2月にSpaceXに買収され、7月に社名をSpaceXAIに変えました(Engadgetの報道)。10月にはマスク氏がSpaceXSIへの再改称を表明しています(Khaleej Times(Reuters配信))。

11月17日時点の公式サイトは「SpaceXSI」表記ですが、この記事では報道で定着している「SpaceXAI」で呼びます。同社の「Grok」の名の付くエージェントは、次の2系統です。

Grok Botについては、Grok Botとは。仕事を任せる"AIの同僚"で解説しました(公式の説明はSpaceXAI Docs「Grok Bot」)。この記事はGrok Buildに絞ります。

GitHubのsuperagent-ai/grok-cliも紛らわしい存在です。Grok APIで動くコミュニティ製のエージェント(MITライセンス)で、READMEに「xAIとは無関係」と明記されています(GitHub「superagent-ai/grok-cli」)。公式のGrok Buildとは別物です。

機能の並びはClaude Codeとほぼ同じで、CLAUDE.mdやClaude Codeのフック設定も読み込む

Grok Buildの基本情報

一方、公式ブログは5月25日付で「SuperGrokとX Premium Plusの全加入者が利用可能」としています(SpaceXAI「Introducing Grok Build」)。上位プランで先に始まり、25日に対象が広がったと読めますが、公式はその経緯を説明していません。

ソース公開の日付も、リポジトリ作成の7月14日(UTC)から報道の16日まで幅があります。1.0.0は8月7日に出て、権限確認の画面で実行予定のスクリプト全文を表示するようになりました(eWeekの報道)。

/planで入るか、Shift+Tabでモードを切り替えます。エージェントはコードベースを調べて計画を書き、承認画面を開きます。承認画面では、計画の行ごとにコメントを付けたり、修正を頼んだりできます(SpaceXAI Docs「Plan Mode」)。

サブエージェントとworktree: 並列で動かしても衝突させない

大きなタスクは、サブエージェントに分けて並列で進めます。組み込みは、何でもできるgeneral-purpose、読んで探すだけのexplore、計画を書くだけのplanの3種類です(SpaceXAI Docs「Subagents」)。

git worktreeとの統合は、公式ブログが強調している点です。grok -wで起動すると、セッションがリポジトリの独立したコピーで動き、並列のエージェントが互いのファイルを上書きしません。サブエージェントもworktreeでの分離を求められます(SpaceXAI Docs「Worktrees」)。

セッションを終えてもworktreeは残るので、grok worktree gcなどで掃除します。Claude Codeにも--worktreeフラグがあり、発想はほぼ同じです。手でworktreeを切る運用はGit worktreeでClaude Codeを並列に走らせるにまとめています。

ヘッドレス実行とACP: 自動化や他ツールに組み込む

ACP(Agent Client Protocol)は、エディタなどのアプリとコーディングエージェントをつなぐ共通規格です。grok agent stdioで起動すると、ACPのエージェントとして標準入出力で応答します。CIで動かすときは、--no-auto-updateで更新チェックを止めるよう公式ドキュメントが勧めています。

AGENTS.md、スキル、フック、MCP: Claude Codeの資産をそのまま読む

ルール: AGENTS.mdに加えてCLAUDE.md、.claude/rules/、.cursor/rules/も読む(SpaceXAI Docs「AGENTS.md」)

フック: Claude Codeの.claude/settings.jsonとCursorの.cursor/hooks.jsonも読む(SpaceXAI Docs「Hooks」)

スキル: SKILL.md形式で、/スキル名のコマンドにもなる(SpaceXAI Docs「Skills, Plugins & Marketplaces」)

Claude Code向けに書いた危険コマンド止めのフックも、流用できる可能性があります(Hooksで危険コマンドを物理的に止める)。ただし同じように動くとは限りません。プロジェクト側のフックは/hooks-trustで信頼を与えるまで動かないので、grok inspectで読み込み状況を確かめます。

本体は無料、推論はサブスクかAPI

Grok Buildの本体(ハーネス)はApache-2.0で、使うこと自体にお金はかかりません。費用が発生するのは、モデルを動かす推論の部分です。払い方は3通りあります。

サブスクでログインする: 10月12日に始まったThe X Subscriptionは、Free(0ドル)、Plus(月8ドル)、Premium(月30ドル)、Super(月100ドル)、Ultra(月200ドル)の5段階(SpaceXAI Docs「Pricing」)。Cursorの料金ページでは、FreeにGrok Buildの限定利用、Plus以上にGrok Buildが含まれている(Cursor「Pricing」)

APIキーで従量課金にする: XAI_API_KEYを設定する。API最新のgrok-4.7は、100万トークンあたり入力2ドル、出力6ドル(20万トークン未満の場合)(SpaceXAI Docs「Grok 4.7」)

自前のモデルを使う: ~/.grok/config.tomlに、OpenAI互換やAnthropic形式のAPIを登録できる

7月にGrok 4.5が出たとき、Engadgetは「Grok Buildの既定モデルになった」と報じました(Engadgetの報道)。その後8月にGrok 4.6が出て、いまの公式ドキュメントはgrok-4.7を最新モデルとして紹介しています。

ところが、Grok Buildの現在の既定モデルは公式ドキュメントに書かれておらず、解説記事も4.5、4.6と分かれます。使うときはgrok modelsで一覧を出し、/modelで選ぶのが確実です。

SpaceX傘下のCursorとの関係

Cursorは8月14日、SpaceXによる買収が完了したと発表しました。4月にSpaceXAIとモデル学習で提携したところから始まった手続きです(Cursor Blog「Cursor is now a part of SpaceX」)。Cursor自体はCursorとは何か。VSCodeと何が違うのかで解説しています。

Grok 4.5は、CursorとSpaceXAIが共同で学習したモデル。Cursorのデータも使われたと報じられている(InfoWorldの報道)

買収完了の2日前に出たGrok 4.6を、Cursorのブログは「私たちがリリースした」と書いている

Cursorの中でClaudeやGPTなど他社モデルを使う分は、この枠に含まれない。初回からAPIの定価で別に課金される(SpaceXAI Docs「What is The X Subscription?」)
