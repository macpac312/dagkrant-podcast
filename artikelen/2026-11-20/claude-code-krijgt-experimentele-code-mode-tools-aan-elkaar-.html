Claude Codeに実験機能「Code Mode」を追加 ——Claudeが複数のツールをつなぐJavaScriptを生成 | gihyo.jp

Anthropicは2026年11月12日、実験機能「Code Mode」を追加したClaude Code v2.1.323を公開した。Code Modeを有効にすると、Claudeは利用者の指示に応じて、複数のツールを組み合わせて作業を進めるスクリプトをJavaScriptで生成する。Claude Codeがそのスクリプトを実行すると、ツールの実行結果を次のツールに直接渡せる。ビルドやテストをバックグラウンドで実行している間も、利用者はClaudeと会話を続けられる。17日には、Anthropicの開発者向けXアカウント、ClaudeDevsでも使い方を紹介した。

Code Modeでは複数のツールをどう使うのか

Code Modeでも、利用者は普段と同じように、何をしたいかを自分の言葉でClaudeに伝える。Code Modeを使わない場合、Claudeはツールを呼び出すたびにその出力を読み、次に何をするかを決める。Code Modeでは、依頼を受けたClaudeが、ツールを呼び出す手順をJavaScriptに書く。ツールの実行結果を次の呼び出しで使う場合も、スクリプト内で受け渡せるため、途中の結果をその都度Claudeに返す必要がない。

たとえば検索結果が多いときは、スクリプトで結果を絞り込み、Claudeが読む必要のある部分だけを返せる。Anthropicはこのほか、多数のファイルに同じ変更を加える作業や、複数の独立したコマンドを並列に実行する作業も用途に挙げている。

Anthropicの公式ガイドには、プログラムが処理を何回まで試すかを決める設定値（maxAttempts）を3回から5回に増やす例がある。ガイドのコードは、retryPolicy関数を定義しているファイルを編集対象とし、関数名を手がかりにそのファイルを探す。Code Modeを使わずに検索と編集を順に進める場合、Claudeは検索結果の一覧を読んで編集先を決めてから、編集ツールを呼び出す。

Code Modeでは、同じ変更を指示されたClaudeが、検索を始める前に編集やテストまでの手順をJavaScriptに書ける。ガイドの例であらかじめ決めているのは「最初に見つかったファイルを編集する」という選び方で、実際の編集先は検索結果で決まる。

Claude Codeがこのスクリプトを実行すると、まず検索コマンドrgがsrcディレクトリ内でfunction retryPolicyを含むファイルを探す。スクリプトは検索結果の先頭にあるパスを編集ツールに渡し、そのファイルのmaxAttemptsを3から5に書き換える。続いて関連するテストを実行し、編集したファイルのパスとテストの出力だけをClaudeに返す。これでClaudeは、途中で一覧を読んで編集先を指定する手順を省ける。

Code Modeを使うには、ネイティブ版のClaude Code v2.1.323以降が必要になる。WindowsではGit for Windowsもインストールしておく。使えるのはターミナルの対話型セッションだけで、VS Code拡張のパネルやデスクトップアプリからは利用できない。

また、ClaudeのサブスクリプションまたはConsoleアカウントでAnthropicに直接接続する必要がある。ゲートウェイ経由の接続や、Amazon Bedrockなどを通じた利用には対応していない。組織でHIPAA対応設定やゼロデータ保持を有効にしている場合も、Code Modeは利用できない。対応モデルや、Code Modeと併用できない設定は、AnthropicのCode Modeの利用要件で確認できる。

Code Modeは初期状態では無効になっている。試すには、Claude Codeを起動するシェルで環境変数CLAUDE_CODE_EXPERIMENTAL_CODE_MODEを1に設定し、claudeで新しいセッションを始める。初回の確認画面で利用者が有効化を選ぶと、Claude Codeが再起動する。後でこのセッションを再開するときも、この環境変数を1に設定した状態で、ターミナルからclaude --continueまたはclaude --resumeを使う。

Code Modeで時間のかかるビルドやテストを実行するとき、スクリプトの完了を待つか、バックグラウンドで実行を続けるかはClaudeが判断する。完了を待つ場合、Claudeが応答するのはスクリプトの実行後で、実行時間の上限は10分となる。v2.1.328より前のバージョンでは、ツールの実行許可を求める画面で利用者の返答を待つ時間も、この10分に含まれていた。v2.1.328以降のManualモードとacceptEditsモードでは、その待ち時間は含まれない。

一方、バックグラウンドではスクリプトを最長2時間実行できる。その間も同じセッションでClaudeと会話を続けられる。利用者は、セッションの起動時に対応する権限モードを選んで、Claudeにバックグラウンド実行を許可することもできる。

たとえば、Code Modeを有効にした状態でclaude --permission-mode autoを実行すると、autoモードでセッションが始まる。bypassPermissionsモードで起動した場合も、Claudeはスクリプトをバックグラウンドで実行できる。このモードでは通常のツール実行時の許可確認と安全チェックが無効になるため、Anthropicは利用をコンテナや仮想マシンなどの隔離環境に限るよう案内している。

いずれのモードでも、バックグラウンド実行を使うには、起動時に--toolsでツール名を指定しない。起動後に権限モードを切り替えた場合は、元のモードに戻す必要がある。v2.1.328より前のバージョンでは、claude --resumeの一覧から選んで再開したセッションでもバックグラウンド実行は使えない。直前のセッションでバックグラウンド実行を使い続けたい場合は、claude --continueで再開する。

なお、autoモードでは、Claude Codeはスクリプトごとに、その内容を実行前に審査する。検索結果から編集先を選ぶ例では、実際のファイルのパスはこの時点では分からない。実行時には、Claude Codeがツールの呼び出しごとに、あらかじめ設定された権限ルールを適用する。denyに該当する操作は拒否し、askに該当する操作は利用者に許可を求める。編集ツールにPreToolUseフックを設定しておけば、ツールに渡されたパスをフックで調べ、特定のファイルへの編集を自動で止めることもできる。
