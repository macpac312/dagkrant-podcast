Cyberverdedigers slaan alarm om kritiek lek in programmeertaal Java

428168 2b29ad2f847123278b23e65dd9b0268b22445489.jpeg 1127 681 Het hoofdkantoor van Oracle, het bedrijf achter Java, in Texas. Foto: Scott Coleman/ZUMA Press block De nationale cyberwaakhonden van Zwitserland en Zuid-Korea waarschuwen voor een 'kritieke' kwetsbaarheid in programmeertaal Java.

Daardoor zouden kwaadwillenden op afstand systemen kunnen overnemen. Veel bedrijven en organisaties gebruiken Java, ook in Nederland. Het Nederlandse Nationaal Cybersecurity centrum (NCSC) laat weten de melding te onderzoeken.

Cybersecurityspecialisten wezen dinsdag einde dag als eerste op de lek. Voor zover bekend is er nog geen misbruik van gemaakt. Oracle, het bedrijf achter Java, kondigde een beveiligingsupdate aan die dinsdagavond 22.00 uur (Nederlandse tijd) zal verschijnen.

Het lek is aangemerkt als ‘kritiek’ door het Amerikaanse cybersecuritybedrijf Calif, hetzelfde bedrijf dat een maand geleden het PHP-lek ontdekte. Toen gingen veel websites in Nederland op zwart vanwege een vergelijkbare melding in de programmeertaal PHP.

Calif zegt met technische details te komen over het Java-lek nadat Oracle met zijn beveiligingsupdate is gekomen. Veelgebruikte programmeertaal Java is een veelgebruikte programmeertaal voor websites, apps en bedrijfssoftware.

Veel bedrijven en instellingen maken gebruik van de software, die zijn wortels heeft in de jaren negentig van de vorige eeuw. Talloze bedrijven maken gebruik van Java, zoals Amazon, Google, Walmart en JPMorgan Chase.

Android, software voor de mobiele telefoon, leunt ook sterk op Java. Behalve de Zuid-Koreaanse cyberwaakhond en Calif wijzen ook het Amsterdamse cybersecuritybedrijf Hadrian en zijn branchegenoot Wiz Security op het lek.

Het zou gaan om een lek in een deel van de software die gebruikt wordt in Java 17 en latere versies. De huidige versie is Java 27. Volgens de berichten heeft het lek een 9,2 op de schaal van 10 in een veelgebruikte classificatie van kwetsbaarheden in software, genaamd CVSS.

Dat is vergelijkbaar met de lekken in PHP die onlangs naar voren kwamen en leidden tot een race tegen de klok om ze te dichten. Op eenzelfde manier kunnen kwaadwillenden via Java systemen overnemen zonder in te loggen.
