Cursor confirms breach distributed malicious Claude Code extensions

On November 13, 2026, Cursor published the results of its two-week investigation into the malicious Claude Code extension that appeared in its marketplace on October 29. The update confirms that an attacker got in through a leaked partner credential and used stolen credentials to plant the tampered extension (Cursor’s November 13 update). Cursor is an AI code editor, and the tampered builds of the Anthropic.claude-code extension, versions 2.1.312 and 2.1.313 for Windows and macOS, were available in its built-in marketplace for about 11 hours (Cursor’s October 29 security notice).

The known exposure is narrow. It covers people who installed or updated to 2.1.312 or 2.1.313 from the Cursor VS Code Extension Marketplace on macOS or Windows between about 2:27 a.m. and 1:35 p.m. Pacific Time on October 29. Anthropic didn’t publish the tampered copy, and Cursor says this wasn’t a vulnerability in Anthropic’s product.

If that window applies to you, or you can’t tell when or where you installed Claude Code inside Cursor, don’t rely on this summary or on your current version number. Follow the checks and remediation steps in Cursor’s security notice.

What Happened in the Cursor Security Breach

Cursor first disclosed the tampered extension on October 29. The November 13 update fills in how the attacker got there. Think of Cursor’s marketplace as a local corner shop that restocks from a big warehouse, the upstream Open VSX registry. The attacker tampered with the corner shop’s own shelf, the cache Cursor uses to serve its marketplace. Cursor’s update says the upstream Open VSX registry never had the malware. That’s Cursor’s assessment of its own incident, and it doesn’t cover other copies or mirrors of the extension.

Microsoft’s October 30 analysis and Cursor’s notice describe what the fake extension tried to do. It sent details about your computer to the attacker and added the attacker’s SSH key. (SSH is a remote-login tool, so this is like copying a spare house key for a stranger.) It also tried to switch on the SSH service, open a “reverse tunnel” back to the attacker’s server, and set itself to restart automatically, using a LaunchAgent on macOS or a scheduled task with a startup-script fallback on Windows.

Cursor’s assessment is that turning on the SSH service needs admin rights the extension doesn’t have on most Macs and PCs, so on those machines the tunnel step would have failed. That isn’t a confirmed result for every affected machine: Microsoft says successful remote access depended on host privileges, SSH configuration, and the attacker’s server, and that the code could still plant keys and persistence even when the tunnel failed.

That’s why Cursor asks affected users to follow its remediation steps regardless. In its November 13 update, Cursor says it believes the incident is contained and that the last attacker activity it saw was on November 1. Containment on Cursor’s side doesn’t remove anything already planted on your machine.

Scale: Two different groups are involved here, and it’s worth keeping them apart. Cursor says at most 5,000 users requested the specific cached versions on October 29 and potentially received the malicious build. Separately, its November 13 update says fewer than 0.01% of customers had API credentials exposed through unredacted coding-agent traces in the shared bucket. Cursor says it has contacted each affected customer directly.

How It Stacks Up: Which Claude Code Sources Were Affected

Microsoft says Anthropic confirmed its systems weren’t compromised and that it didn’t develop the malicious package, and that all evidence points to the incident being limited to Cursor’s marketplace. Cursor also says it validated every other extension in its marketplace and that the Cursor app itself and its official updates weren’t affected. The problem was the shelf Claude Code sat on inside Cursor, not Anthropic’s own releases.

The Reaction

Cursor apologized in its update, saying “we can and must do better,” and listed what it has changed: moving inference off Fireworks, rotating its internal credentials, adding secret scanning, and rebuilding the extension marketplace (Cursor). Wider reaction is still forming.

What to Do Next

Start with timing, not your current version. A newer version today doesn’t prove an affected build never ran, because the payload drops standalone persistence scripts that keep running after an update or uninstall.

If you installed or updated Claude Code in Cursor around October 29, or you aren’t sure, use the check in Cursor’s security notice. It looks for the attacker’s SSH key, labeled svc-telemetry, in your authorized keys file. Treat that label as a starting point, not a final verdict.

Microsoft advises confirming the key against the fingerprint published in the indicators of compromise, and a missing label doesn’t replace checking installation records and the other indicators if you installed during the window. If the attacker’s key is there, Cursor’s guidance for affected machines goes well beyond a version check:

If Cursor emailed you or your team admin about exposed API keys, rotate the specific keys it listed.

On Windows

Cursor’s notice points to a scheduled task named SysMon, a sysmon.cmd file in your Startup folder, and an unfamiliar key in your SSH authorized keys file.

On macOS

Cursor’s notice points to a LaunchAgent labeled com.apple.sysmond and the svc-telemetry key in ~/.ssh/authorized_keys. Turn off Remote Login if you don’t normally use it.

Our Take

By Cursor’s account, the tampering happened on its own marketplace cache rather than the upstream Open VSX registry, and Microsoft says the Visual Studio Marketplace and npm weren’t affected. If you’re a Cursor user who installed or updated extensions on October 29, run Cursor’s check today.

If you’re a small business owner, ask your contractors directly. It’s a five-minute question that could save you a very bad month.

The root cause sits with credentials: a partner’s access key, and secrets left unredacted in stored coding traces, gave the attacker a path to the marketplace. Credit to Cursor for publishing exact versions, times, indicators, and remediation scripts quickly. That’s what makes self-checking possible.

Wrapping Up

The tampered builds sat on Cursor’s marketplace cache for about 11 hours, and Cursor’s investigation traces them back to a leaked partner key. If you might have pulled one of them, follow Cursor’s notice from start to finish. Next time an app offers its own copy of an extension, remember that you’re trusting that store as much as the developer.
